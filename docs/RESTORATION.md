# Restored capabilities and data provenance

The active prediction model is in `backend/serious_outcome.py`. The supplied Python sources are preserved under `legacy/app/`, `legacy/pipeline/`, `legacy/flows/`, and `legacy/jobs/`. An untouched source snapshot is retained under `legacy/original_sources/`. The supplied screenshots and original README are in `docs/reference/`. Credentials, compiled bytecode, and serialized pickle models were not imported.

## Original application

Run from the repository root with Python 3.11 and `config/requirements/legacy.txt`:

```powershell
python -m pip install -r config/requirements/legacy.txt
python -m streamlit run legacy/app/streamlit_app.py
```

## Supplied datasets

| File | Rows | Meaning |
| --- | ---: | --- |
| `data/bronze/reviews.csv` | 2,000 | Synthetic drug review templates generated by the original ingestion code |
| `data/silver/labels.parquet` | 2,000 | Keyword taxonomy labels derived from those review texts |
| `data/gold/scores.parquet` | 2,000 | Historical model output; row-to-text alignment is not validated |
| `data/gold/signals.parquet` | 1,345 | Historical weekly aggregates from the original demo pipeline |
| `data/legacy/side_effects.duckdb` | — | Original supplied database retained as an artifact |

These reviews are not real FAERS records. For example, supplied review 1 says "tremor" and has a neurological label, while its cached neurological score is approximately 0.057 and cardiovascular score is approximately 0.958. Cached scores and signals must therefore be treated as illustrative legacy artifacts. They are retained without being rewritten, so the supplied files remain available for inspection.

The report-level seriousness models use live FAERS records independently of this synthetic review pipeline. FAERS report classification concerns submitted reports; it does not estimate a patient's personal medical risk or establish drug causality.

## Reliability repairs

- Package imports work for both Streamlit entry points and `app.*` library imports; the separate NLP page can import its parent application modules.
- Scoring assigns `predict_proba` columns to their corresponding targets and preserves review row alignment. The original implementation indexed probability rows as if they were target columns.
- Training validates binary labels, rejects conflicting duplicate annotations and sparse classes, removes normalized exact-text duplicates before splitting, and fits TF-IDF only on the training partition. Metrics and the classification report come from a held-out partition. MLflow records `evaluation_metadata.json`, including the split sizes and limitation.
- On the supplied data, 913 repeated texts are removed, leaving 1,087 distinct reviews: 815 training and 272 held-out. Held-out micro/macro F1 still reach 1.0 because the synthetic templates and labels share an explicit keyword taxonomy. This measures recovery of that rule, not clinical validity or generalization to real narratives.
- Pipeline output folders are created as needed. DuckDB persistence writes actual labels/scores/signals tables in addition to Parquet files.
- Weekly alerts use seven complete days, apply a consistent serious-only cohort to numerator and denominator counts, retain all provided reaction counts, enforce the configured burst threshold, preserve output date metadata, and use Windows-compatible artifact filenames.
- The archived GitHub workflow installs the complete legacy application dependency list. Notifications are sent only when corresponding environment variables are configured and the job is explicitly run by its workflow or operator.

Run regression checks with `python -m unittest discover -s tests -p test_legacy_pipeline.py -v`.

## Remaining methodological limits in the original analyses

- Narrative sentiment and clinical flags are keyword rules. They do not resolve negation, distinguish personal experience from quoted history, or support diagnosis.
- Legacy graph expectations normalize a truncated set of reaction counts; its z values are exploratory display weights and are not calibrated statistical significance tests.
- The original rolling burst function includes the current observation in its reference window. Weekly demo category z scores use the entire available series. Neither is an out-of-sample anomaly detector.
- Aggregate PRR/ROR use spontaneous report counts with reporting bias and incomplete reaction-count pages. Signal flags are screening heuristics. Weighted severity scores can exceed 100 because one report may contain several outcome flags; they are not percentages or calibrated risks.
- The original time-series helper returns daily receipt-date counts, although some original view labels say "weekly". The modern UI should aggregate to actual weeks when displaying weekly charts.
- FAERS case narratives are unavailable through the original openFDA drug/event integration; the narrative alternatives are uploaded text or device-event text. Source labels must remain explicit.
